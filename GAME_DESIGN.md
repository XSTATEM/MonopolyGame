# Trade Monopoly — полная документация

Единый справочник по всем механикам, формулам, аккаунтам и функциям приложения.
Актуально на дату последнего обновления файла; источник истины — код в `server/`.

Стек: чистый Node.js (`http` + `ws`, без фреймворков) на сервере, ванильный
JS/HTML/CSS на клиенте. Всё игровое состояние держится в памяти процесса
(`Map` комнат в `server.js`); персистентно на диск сохраняются только
аккаунты игроков (`server/data/users.json`).

## 1. Архитектура кода

- **`server/public/engine.js`** — «движок»: вся игровая логика в чистых
  функциях без сети/таймеров/DOM. Каждая функция-действие мутирует
  переданный объект `room` и возвращает `{ok:true, ...}` либо `{error:"..."}`
  (иногда с флагом `stillChanged: true`, если состояние изменилось несмотря
  на ошибку — например, сделка отклонена, но список pendingTrades уже
  обновился). UMD-модуль: `module.exports` в Node, `window.GameEngine` в
  браузере — один и тот же файл используется и сервером, и офлайн-режимом.
- **`server/server.js`** — тонкая сетевая обвязка: WebSocket-сервер держит
  комнаты (`Map<code, room>`) и соединения (`Map<ws, conn>`), маршрутизирует
  входящие `{type: "..."}` сообщения в вызовы `engine.*`, рассылает всем в
  комнате обновлённое состояние через `engine.buildStatePayload(room, playerId)`.
  Также поднимает статический HTTP-сервер (раздаёт `public/`) и несколько
  JSON REST-эндпойнтов для аккаунтов/магазина (см. §15). Единственный кусок
  логики, которого нет в движке — таймер фазы торгов (`syncTradeTimer`),
  потому что движок принципиально не заводит таймеров.
- **`server/public/index.html`** — весь клиент в одном файле: разметка,
  стили и скрипт. Для онлайн-игры открывает WebSocket и просто рендерит
  присланный `state`; для офлайн-игры (`localDispatch`) держит комнату
  прямо в браузере и вызывает функции `engine.js` напрямую, дублируя
  switch-case из `server.js`.
- **`server/users.js`** — файловое хранилище аккаунтов (`data/users.json`),
  scrypt-хэширование паролей, начисление очков рейтинга, покупка/экипировка
  скинов.
- **`server/public/skins.js`** — общий (сервер+клиент) каталог косметики:
  паки аватаров и темы стола.

Важно при разработке: `require()` в Node кэширует модули — после правки
`engine.js`/`server.js` сервер нужно перезапускать; страницы браузера тоже
нужно перезагружать, так как `engine.js` подключается туда же напрямую
через `<script>`.

## 2. Аккаунты и авторизация

Хранилище — `server/data/users.json`, простой JSON-объект
`usernameKey -> запись`. Сессий нет: почти каждый HTTP-запрос управления
профилем заново подтверждается паролем (то же доверие, что и при входе в
комнату по WS).

**Регистрация** (`users.register`):
- ник 2–20 символов, разрешены буквы (лат/рус), цифры, пробел, `-`, `_`;
- пароль ≥ 4 символов;
- ник должен быть свободен (сравнение регистронезависимое — `usernameKey`
  приводит к нижнему регистру и обрезает пробелы).
- Пароль хэшируется через `crypto.scryptSync(password, salt, 64)` с
  индивидуальной случайной солью (16 байт) на пользователя; в открытом виде
  пароль никогда не хранится и не передаётся дальше сервера.
- Новый аккаунт стартует с `points: 0`, набором `ownedAvatarPacks: ["base"]`,
  `ownedBoardSkins: ["default"]`, экипированы базовые.

**Вход** (`users.login`) — сверка scrypt-хэша пароля с солью записи.

**Публичный профиль** (`publicProfile`, то, что уходит клиенту) —
`{username, gender, avatar, avatarPhoto, points, ownedAvatarPacks,
ownedBoardSkins, equippedAvatarPack, equippedBoardSkin}`.

**Управление профилем** (все требуют пароль — `authenticate(username, password)`):
- `updateProfile(username, password, gender, avatar)` — смена пола/аватара.
  Аватар-эмодзи должен принадлежать одному из уже купленных паков; либо
  специальное значение `"PHOTO"`, которое включает показ загруженного фото
  вместо эмодзи (требует, чтобы фото уже было загружено).
- `changePassword(username, password, newPassword)` — новый пароль ≥ 4
  символов, генерируется новая соль.
- `setPhoto(username, password, photoDataUrl)` — загрузка фото профиля;
  проверяется префикс data URL (`data:image/(png|jpeg|jpg|webp);base64,`) и
  максимальная длина строки 400 000 символов (~300 КБ после base64 —
  клиент обязан сжать фото перед отправкой). Успешная загрузка сразу
  выставляет `avatar = "PHOTO"`.
- `buySkin(username, password, skinId, kind)` — покупка скина за очки
  рейтинга (`kind` = `"avatarPack"` | `"boardSkin"`); проверяет, что скин
  ещё не куплен и что очков хватает; списывает стоимость, добавляет id в
  массив владения.
- `equipSkin(username, password, skinId, kind)` — экипировка уже купленного
  скина (проверка владения обязательна).
- `addPoints(username, amount)` — начисление очков рейтинга (вызывается
  сервером при завершении партии, см. §13); возвращает новый баланс.
- `getLeaderboard(limit=50)` — все аккаунты, отсортированные по `points`
  по убыванию, публичные профили.

Вход в игровую комнату (`handleJoin` в `server.js`) требует аккаунт: ник —
это логин, доступ закрыт паролем, поэтому нельзя присвоить чужой прогресс,
просто зная ник. При входе `authMode` — `"register"` или `"login"`;
успешный вход подтягивает `points`/`equippedBoardSkin` из аккаунта в
игровой профиль `engine.addPlayer`.

## 3. Комнаты, подключение, лобби

- Код комнаты — произвольная строка до 20 символов, регистр верхний
  (по умолчанию `"MAIN"`), задаётся при входе.
- `GET /api/rooms` — список активных (есть хоть один игрок) комнат:
  код, число игроков, число подключённых сейчас, число ещё не
  обанкротившихся, фаза, номер события, окно торгов, время создания.
  Используется экраном выбора комнаты в онлайн-режиме.
- Длительность фазы свободных торгов настраивается при создании комнаты —
  одно из `[30000, 90000, 180000]` мс (иначе используется дефолт
  `DEFAULT_TRADE_WINDOW_MS = 90000` мс, либо переменная окружения
  `TRADE_WINDOW_MS`).
- Первый вошедший в лобби становится хостом (`hostPlayerId`); если хост
  отключается ещё на этапе лобби, хостом становится следующий подключённый
  игрок.
- Переподключение по тому же нику восстанавливает того же игрока
  (`connected: true`), если он не был подключён в этот момент кем-то
  другим (иначе — ошибка «имя уже занято в комнате»). Отключение просто
  ставит `connected: false`, а не удаляет игрока — состояние (кэш, акции,
  недвижимость) сохраняется всю партию.
- `startGame` — начать может только хост, минимум 2 игрока, только из фазы
  `lobby`. Стартовый капитал каждого игрока — **$150 000**.

## 4. Ход игры: раунды, фазы, кубики

Фазы комнаты (`room.phase`): `lobby → roll ⇄ trade → ended`.

- **`roll`** — фаза ходов: игроки по очереди (`turnOrder`/`turnIndex`)
  бросают кубики, покупают/платят, ход переходит к следующему.
- **`trade`** — фаза свободных торгов между всеми событиями: можно
  продавать акции банку, предлагать сделки другим игрокам, а также
  использовать спецдействия контрольного пакета, шпионаж/дискредитацию,
  расследование, кредиты, шорты. Таймер (только на сервере — сам движок
  таймеров не заводит) автоматически завершает фазу по истечении
  `tradeWindowMs`; также можно завершить досрочно голосованием (см. ниже).
- **`ended`** — игра окончена, остался один не обанкротившийся игрок.

**Раунд = один полный круг по столу**, а не фиксированное число бросков:
`room.turn` считает ходы внутри раунда, `roundLen = число игроков в
turnOrder`. Когда `turn > roundLen`, наступает биржевое событие
(`marketEvent`) — это специально сделано зависящим от числа игроков, чтобы
темп игры не «дёргался» при малом числе игроков и не наступал раньше, чем
все успели сходить, при большом.

**Бросок кубиков** (`rollDice`):
1. Сначала — фоновый рыночный шум (`ambientJitter`): каждой из 20 компаний
   применяется случайное отклонение цены -1.5%..+1.5% (до множителя
   волатильности тира), чтобы рынок жил и между крупными событиями.
2. Случайно выбираются `row` (1–12) и `col` (1–12) — клетка стола
   12×12 = 144 клетки (`BOARD`). 16 из 144 клеток — недвижимость (`RE:cityId`),
   остальные — тикеры компаний (с повторами).
3. Результат сохраняется в `room.pendingRoll = {playerId, row, col, ticker
   или realEstateId}` — дальше игрок выбирает действие.

**Действия после броска на клетку с акциями:**
- `buyFromRoll(pct)` — купить 10% или 25% компании по текущей цене + комиссия
  банка (зависит от репутации, см. §7). Возможно, только если у банка ещё
  есть свободный объём (суммарно у всех игроков ≤ 100%). Покупка двигает
  цену вверх: `applyPriceDelta(ticker, +2 * (pct/10))` (т.е. +2% за каждые
  10% купленного пакета, до множителя волатильности тира).
- `dividendFromRoll()` — отказ от покупки, если пакет уже частично выкуплен
  другими игроками: **обязательная** плата в пользу текущих держателей,
  пропорционально их долям (не «дивиденды», а штраф за отказ). Формула:
  `amount = price * TIER_FORCED_PAYMENT_PCT[tier] * (totalOwnedPct/100) *
  dividendMultiplier * (2 если компания под сквиз-аутом иначе 1)`, где
  `TIER_FORCED_PAYMENT_PCT = {A:0.03, B:0.05, C:0.08}`. Если пакет
  полностью под контролем одного игрока (>50%, других держателей нет) —
  этот путь недоступен, вместо него применяется `setForcedPrice`.
- `setForcedPrice(amount)` — если пакетом единолично владеет один игрок
  (>50%, без других держателей), именно он назначает сумму выкупа
  (произвольную!). Если сумма превышает «справедливую» ставку
  (`price * TIER_FORCED_PAYMENT_PCT[tier] * heldPct/100`) более чем в
  `FORCED_PRICE_EXCESSIVE_MULT = 4` раза — репутация контролёра падает на
  12, и с вероятностью 50% «Антимонопольная служба США» конфискует
  `ANTITRUST_CONFISCATE_PCT = 15`% его пакета обратно банку (плюс цена
  компании падает).
- `payForcedPrice()` — цель платит назначенную сумму контролёру напрямую.
- `skipRoll()` — пропустить: доступно, только если клетка свободна (нет
  чужих держателей акций / недвижимость не занята чужим).

**Действия на клетке недвижимости** (см. §6): `buyRealEstateFromRoll`,
`upgradeRealEstateFromRoll`, `payRealEstateRentFromRoll`.

После любого завершающего действия хода (`afterRollAction`): `pendingRoll`
и `pendingForcedPrice` сбрасываются, `room.turn++`; если раунд закончен —
наступает `marketEvent`, иначе ход переходит следующему игроку по кругу.
После каждого шага проверяется условие конца игры (`checkEndGame`).

**Досрочное завершение фазы торгов** (`readyEndTradeWindow`) — toggle-кнопка
«готов завершить торги»: как только все ещё активные (не банкроты) игроки
нажали готовность — фаза заканчивается без ожидания таймера. Повторное
нажатие тем же игроком отменяет его готовность.

## 5. Акции компаний

20 компаний, тир `A`/`B`/`C` (влияет на волатильность и другие формулы),
5 секторов:

| Сектор | Компании |
|---|---|
| Технологии | Apple(A), Microsoft(A), Google(A), NVIDIA(B), IBM(B) |
| Интернет и медиа | Amazon(B), Disney(A), Яндекс(C), VK(C) |
| Потребительские товары | McDonald's(A), Nike(B), Coca-Cola(B), Walmart(B), Durex(C) |
| Промышленность и транспорт | Boeing(A), 3M(B), Аэрофлот(C) |
| Финансы и сырьё | Сбербанк(B), Газпром(C), Магнит(C), МТС(C) |

**Стартовая цена по тиру** (`TIER_PRICE`): A = $40 000, B = $20 000,
C = $8 000. Цена не может упасть ниже 10% от стартовой цены тира (`floor`).

**Волатильность по тиру** (`TIER_VOL`, множитель к любому % изменения
цены — от событий, покупок, спецдействий): A = 0.7×, B = 1.0×, C = 1.6×
(«Низкая/Средняя/Высокая» в UI).

**Комиссия банка при покупке** зависит от репутации покупателя, см. §7.

| Вашингтон | $135 000 | $5 400 |
| Майами | $130 000 | $5 200 |
| Чикаго | $120 000 | $4 800 |

| Остин | $95 000 | $3 800 |
| Даллас | $85 000 | $3 400 |

- **Текущая цена** = базовая цена города × рыночный фактор города
  (`factor`, дрейфует каждое биржевое событие) × `(1 + уровень × 0.4)`.
- **Текущая рента** = базовая рента × фактор × `(1 + уровень × 0.6)`,
  дополнительно × `dividendMultiplier` (эффект «Дивидендный сезон»).
- **Улучшение** (`upgradeRealEstateFromRoll`) — до `MAX_RE_LEVEL = 4`
  уровней; стоимость следующего уровня = `текущая цена × 1.5`.
- **Рыночный дрейф** (`processRealEstate`, раз в событие) — фактор каждого
  города умножается на случайное `-2%..+4%` (лёгкий уклон вверх), с
  ограничением `factor ∈ [0.6, 2.2]`.
- Рента **не начисляется пассивно** — платится только когда кто-то
  попадает броском кубиков на занятую чужую клетку
  (`payRealEstateRentFromRoll`).
- Покупка облагается комиссией банка по репутации, как и акции (§7).
- При банкротстве или экстренной распродаже долга недвижимость уходит
  обратно банку (см. §7 «Принудительное покрытие долга»).

## 7. Кредиты банка и репутация

**Репутация** (`reputation`) — число 0..100, старт 50
(`REPUTATION_START`). Влияет на комиссию банка, условия кредита и
формулы шпионажа/дискредитации/расследования.

Изменения репутации по событиям:
| Событие | Δ |
|---|---|
| Банкротство | −30 |
| Слишком завышенная цена выкупа доли (>4× справедливой) | −12 |
| Поймали на шпионаже (провал) | −8 |
| Провальная попытка дискредитации (раскрылась публично) | −10 |
| Разоблачён успешным расследованием цели | −10 |
| Просрочка минимального платежа по кредиту | −10 |
| Полное погашение кредита | +3 |

**Комиссия банка при покупке** (`bankFeePct`, акции и недвижимость):
- репутация ≥ 70 → 0%
- 40–69 → 1.5%
- 20–39 → 3.5%
- < 20 → 6%

**Условия кредита** (`loanTerms`, зависят от репутации и чистого капитала
`netWorth`):
- лимит = `netWorth × (0.10 + (репутация/100) × 0.35)`
- ставка за событие = `clamp(28 − репутация × 0.22, 4, 28)`% (округление
  до 0.1%)

**Взять кредит** (`takeLoan`) — один активный кредит одновременно,
сумма ≤ лимита; деньги сразу зачисляются на счёт.

**Погасить кредит** (`repayLoan`) — частично или полностью; при остатке
≤ $1 кредит закрывается автоматически, репутация +3.

**Автообслуживание кредита** (`processLoans`, вызывается на каждое
биржевое событие):
1. Начисление процентов: `principal += principal × ratePct/100`.
2. Минимальный платёж = 15% от текущего остатка долга, списывается
   автоматически, если хватает наличных.
3. Если наличных не хватает — просрочка (`missedPayments++`), репутация
   −10. После **3 просрочек подряд** банк принудительно взыскивает весь
   остаток долга (списывает с баланса, что может увести его в минус) и
   запускает принудительное покрытие долга.

**Принудительное покрытие долга** (`settleDebt`, вызывается всюду, где
баланс может уйти в минус — рента, налог, взыскание кредита):
1. Пока `cash < 0` — банк принудительно распродаёт акции игрока по
   текущей цене (по одному тикеру за раз), каждая продажа дополнительно
   давит цену вниз (`applyPriceDelta(ticker, −2 × pct/10)`).
2. Если акций не хватило — распродаётся недвижимость по **85%** от
   рыночной цены (штраф за экстренность), уровень улучшений обнуляется.
3. Если и этого не хватило — игрок объявляется банкротом: все holdings
   обнуляются, кредит списывается, репутация −30, банкрот выбывает из
   активной игры.

## 8. Свободные торги (фаза trade) и сделки между игроками

- **Продажа банку** (`sellBank`, только в фазе `trade`) — 10% или 25%
  пакета по текущей цене; давит цену вниз так же, как принудительная
  продажа (`−2% × pct/10`). Покупка у банка **в этой фазе закрыта** —
  специально, чтобы окно свободных торгов не превращалось в обычную
  скупку (см. `buyBank()`, которая всегда возвращает ошибку).
- **Предложение сделки** (`proposeTrade(to, ticker, pct, price)`) — прямая
  сделка игрок-игроку по произвольной цене (не обязана совпадать с
  рыночной); требует, чтобы у продавца было достаточно акций.
- **Ответ на сделку** (`respondTrade(id, accept)`) — получатель принимает
  или отклоняет; при принятии проверяется, что у продавца всё ещё есть
  акции и у покупателя хватает денег (иначе ошибка, но список предложений
  уже актуализирован — `stillChanged: true`). Сделка **не двигает
  рыночную цену компании** — только банк-операции двигают цену.

## 9. Спецдействия контрольного пакета (>50%)

Доступны только в фазе `trade`, и только если рынок не заморожен
(`room.frozen`, эффект карты «Заморозка цен»).

- **Негативная информация** (`ctrlNegativeInfo`, $10 000) — держатель
  контрольного пакета ЛЮБОЙ своей компании может «слить» негатив о **чужой**
  компании: −15% к цене. Кулдаун — раз в 2 события на одну и ту же
  компанию-цель.
- **PR-кампания / байбэк** (`ctrlPrCampaign`, 5% капитализации компании) —
  требует контроля именно этой компании (>50%); +10% к цене. Кулдаун —
  1 раз за событие на компанию.
- **Инсайд** (`ctrlInsiderPeek`, $5 000) — требует контроля хотя бы одной
  компании, максимум раз за событие на игрока. Подсматривает верхнюю карту
  колоды новостей до её розыгрыша; затем `ctrlInsiderResolve(action)` —
  оставить карту наверху (сыграет как обычно) или переложить в конец
  колоды (`moveToBack`, откладывает её эффект на будущее). Пока карта не
  разрешена, никто другой не может подсмотреть новую (`pendingInsider`
  блокирует повтор).
- **Сквиз-аут** (`ctrlSqueezeOut`, требует >75% пакета) — принудительный
  выкуп всех миноритариев по текущей цене (сумма = Σ по всем чужим
  держателям `цена × их_доля/100`); после этого компания помечается
  `squeezedOut: true`, что **удваивает** будущие штрафы за отказ от
  покупки (`dividendFromRoll`, множитель ×2).
- **Шорт** (`ctrlShort`, залог $5 000) — ставка на падение цены к
  следующему биржевому событию; один открытый шорт на пару игрок+компания
  одновременно. Разрешение — см. §12.

## 10. Шпионаж, дискредитация и расследование

Все три действия доступны только в фазе `trade`. Личность инициатора
**никогда не публикуется в открытую** при успехе — она известна только
серверу (`room.spyIncidents`) и может быть раскрыта только через успешное
расследование самой цели.

**Шпионаж** (`ctrlEspionage`, $8 000, кулдаун — раз за событие на
цель):
- Шанс успеха = `clamp(0.75 − репутация_цели/500, 0.25, 0.75)` — чем выше
  репутация цели, тем сложнее её «прошпионить».
- Успех: активы цели (holdings + недвижимость) раскрываются шпиону на
  2 следующих события (`reveals`); в общую ленту падает анонимная запись
  «кто-то шпионил»; в `spyIncidents` записывается настоящий подозреваемый.
- Провал: шпион пойман, его репутация −8, в ленте — публичная запись с
  именем шпиона.

**Дискредитация** (`ctrlDiscredit`, кулдаун — раз за событие на цель):
- Стоимость = `5000 + репутация_цели × 300` (дороже атаковать
  репутабельного игрока).
- Шанс успеха фиксированный — 55%.
- Успех: репутация цели −15, анонимная запись в ленте, случай записан в
  `spyIncidents`.
- Провал: репутация инициатора −10, **публичная** запись с его именем.

**Расследование** (`ctrlInvestigate`) — цель шпионажа/дискредитации
пытается вычислить виновного по самому старому нераскрытому случаю против
неё:
- Стоимость = `max(3000, round(clamp(cash × 0.04, 5000, 50000) − репутация
  × 40))` — чем богаче цель, тем выше базовая стоимость (доступно более
  качественное расследование), но высокая репутация её снижает.
- Шанс успеха = `clamp(0.28 + репутация/380 + cash/2 500 000, 0.2, 0.85)`.
- Успех: раскрывает `suspectId`/`suspectName` **только вызвавшему игроку**,
  репутация уличённого −10, публичная запись в ленте с именем виновного.
- Провал: деньги потрачены, случай снят с очереди, виновный остаётся
  неизвестным.

Клиенту в `state.mySpyIncidents` присылаются только нераскрытые случаи
**против него** (`id, kind, eventCount`, без suspectId), плюс
`investigationPreview: {cost, chancePct}` — предпросмотр текущей
стоимости/шанса для UI.

## 11. Карты новостей (колода событий)

Биржевое событие (`marketEvent`) происходит после полного круга ходов
(каждый игрок сходил по разу). Порядок действий внутри события:

1. `eventCount++`, сброс `dividendMultiplier` к 1.
2. **Кубик волатильности**: 1–6, при 1–2 → −5% всем компаниям, при 5–6 →
   +5%, при 3–4 → 0% (сила по факту разная у разных компаний из-за их
   тира волатильности).
3. Обслуживание кредитов (`processLoans`) и дрейф рынка недвижимости
   (`processRealEstate`).
4. Розыгрыш верхней карты колоды (`deckOrder`, перемешивается заново, если
   закончилась — `deckPos >= length`). Карта одного из 4 типов:
   - **`global`** (12 карт) — влияет на ВСЕ компании: от «Мировой кризис»
     (−15%) до «Бум на рынке» (+15%).
   - **`sector`** (20 карт, по 4 на каждый из 5 секторов) — влияет только
     на компании своего сектора, разброс от −20% до +20%.
   - **`company`** (24 карты) — влияет на одну случайно выбранную
     компанию (разброс от −25% до +22%); часть карт дополнительно
     пропускает штраф-«дивиденды» по этой компании на 1 ход
     (`skipDividendUntil`).
   - **`special`** (12 карт, 6 уникальных × 2 копии каждая) — особые
     эффекты:
     - `freeze` («Заморозка цен») — до конца события цены не меняются
       (`room.frozen = true`), спецдействия контрольного пакета
       блокируются.
     - `buyback` («Принудительный выкуп») — банк выкупает по 10% у каждого
       держателя ≥10% одной случайной компании по текущей цене.
     - `extra_trade` («Доп. фаза торгов») — сразу после этой фазы торгов
       стартует ещё одна, без новой карты новостей.
     - `audit` («Аудит») — у каждого игрока с отрицательным балансом
       немедленно запускается принудительное покрытие долга.
     - `double_dividend` («Дивидендный сезон») — `dividendMultiplier = 2`
       до следующего события (удваивает штрафы за отказ от покупки и
       ренту недвижимости).
     - `tax` («Налоговая проверка») — каждый активный игрок платит банку
       2% от своего чистого капитала, с последующим покрытием долга при
       необходимости.
5. Разрешение открытых шортов, размещённых до этого события
   (`resolveShorts`, см. §12).
6. `room.turn = 1`, старт новой фазы торгов (`startTradeWindow`).

## 12. Шорты

Ставка на падение цены компании к следующему биржевому событию.

  ($10 000);
- иначе залог сгорает.

## 13. Конец игры и очки рейтинга

`checkEndGame` — как только из всех игроков остаётся ровно один не
банкрот (и всего игроков было больше 1), фаза становится `ended`:
- Очки за победу = `max(1, round(итоговый_чистый_капитал / 1000))`.
- `room.lastGamePointsAward = {playerId, amount}` — сервер (`server.js`,
  `syncAccountPoints`) забирает это один раз за тик и дописывает очки в
  персистентный аккаунт победителя через `users.addPoints`, обновляя
  отображаемое значение в комнате.
- `room.gameResult` — не одноразовый (в отличие от award), хранится в
  комнате до начала новой партии: `{winnerId, winnerName, netWorth,
  pointsEarned, ranking:[{id,name,netWorth,bankrupt,points}]}`,
  отсортированный по убыванию чистого капитала — используется экраном
  завершения игры (ранги, медали, итоги).
- Чистый капитал (`netWorth`) = наличные + Σ(доля_акции/100 × текущая цена)
  по всем компаниям + Σ(текущая цена недвижимости) по всем городам в
  собственности − остаток кредита.

**Новая партия** (`newGame` / `newGameKeepPlayers`) — реванш с теми же
игроками (имена, пол, аватар, накопленные очки, экипированный скин стола)
но свежим состоянием рынка/города/колоды; фаза сразу `roll` (без
повторного лобби). На сервере: старая комната в `rooms` заменяется на
свежую с тем же кодом, у всех подключений (`connections`) обновляется
`playerId` на новый id того же игрока по имени.

## 17. Офлайн-режим (хот-сит)

`localDispatch(obj)` в `index.html` — зеркало серверного switch-case,
вызывающее те же функции `engine.js` напрямую на локальном объекте
`localRoom`, без сети. Позволяет играть несколькими игроками за одним
устройством по очереди («hot-seat»); все формулы/правила идентичны
онлайн-режиму, так как используется тот же движок. Отличие только в слое
доставки состояния: вместо broadcast по WS — прямой вызов `refreshLocal()`
после каждого действия, который перерисовывает UI из `localRoom` под
текущего «активного» локального игрока (`viewAs`).

## 18. Уведомления (toast) и прочие мелочи

**Toast-уведомления** (`showToast`/`dismissToast`/`detectNotifications`) —
всплывающий стек в правом углу (`#toastStack`), автоматически определяет
важные события, сравнивая предыдущий и новый снимок состояния
(`detectNotifications(prevState, msg)`), вызывается и в онлайн-обработчике
`ws.onmessage`, и в офлайновом `refreshLocal()`. Триггеры:
- новый случай шпионажа/дискредитации против зрителя;
- принудительная цена впервые назначена против зрителя;
- новое входящее предложение сделки;
- рост числа просроченных платежей по кредиту;
- банкротство любого игрока;
- доступность инсайдерского подсматривания карты;
- завершение игры.

**Прочее:**
- `fmt(n)` — единый форматтер денег: `"$" + Math.round(n).toLocaleString("ru-RU")`.
- Пинг WS-соединений каждые 30 секунд (`pingInterval`) с закрытием
  «зависших» сокетов, которые не ответили `pong`.
- Статика раздаётся из `server/public/`; любой не-API путь без
  соответствующего файла отдаёт `index.html` (простой SPA-fallback,
  без выделенного роутера).
- Папка `design/` (референсные скриншоты/PDF) в репозитории намеренно не
  версионируется как часть исходного кода приложения.
