# Развёртывание «Биржи» на своём сервере

Игра — один процесс Node.js (`server/server.js`): он раздаёт веб-клиент, API аккаунтов
и WebSocket онлайн-партий. Внешняя база не нужна: аккаунты лежат в `users.json`,
идущие партии сервер держит в памяти и сохраняет в `rooms.json` (каждые 30 секунд
и при остановке), так что перезапуск или обновление не обрывают игру — клиенты
переподключаются сами.

Схема на сервере:

```
Интернет ──443/80──▶ nginx (TLS, gzip, лимит попыток входа) ──▶ 127.0.0.1:8792 Node.js (systemd: birzha)
                                                                     │
                                                    /var/lib/birzha: users.json, rooms.json, backups/
```

## Что понадобится

- VPS с **Ubuntu 22.04 / 24.04** или **Debian 12**, 1 vCPU и 512 МБ памяти хватает
  на десятки одновременных партий. Доступ по SSH под `root` или пользователем с `sudo`.
- **Домен** (или поддомен), A-запись которого указывает на IP сервера. Без домена
  игра заработает по `http://IP`, но браузер не даст установить её как приложение (PWA),
  а мобильное приложение требует HTTPS.
- Открытые порты 22, 80, 443 у хостинга (скрипт сам настроит `ufw` на сервере).

## Установка за одну команду (с Windows)

В PowerShell из корня проекта:

```powershell
.\deploy\deploy.ps1 -Server 203.0.113.10 -Install -Domain game.example.ru -Email you@example.ru
```

Скрипт упакует `server\` и `deploy\`, скопирует их на сервер по `scp` и запустит
`deploy/install.sh`. Если входите не под root — добавьте `-User имя` (понадобится пароль sudo),
нестандартный порт SSH — `-SshPort 2222`. Перенести локальные аккаунты с вашего компьютера:
`-ImportData`.

## Установка вручную (с любой ОС)

```bash
# на своём компьютере
scp -r server deploy root@203.0.113.10:/root/birzha/
# на сервере
ssh root@203.0.113.10
sudo bash /root/birzha/deploy/install.sh --domain game.example.ru --email you@example.ru
```

Без домена: `sudo bash deploy/install.sh --no-tls`. Все параметры: `bash deploy/install.sh --help`.

Что делает `install.sh` (его можно запускать повторно):

1. ставит nginx, certbot, ufw и Node.js 22 LTS (официальная сборка с nodejs.org,
   с проверкой контрольной суммы);
2. создаёт системного пользователя `birzha` без shell и каталог данных `/var/lib/birzha`;
3. пишет настройки в `/etc/birzha.env`, ставит службу `birzha` (systemd, с изоляцией:
   процесс может писать только в каталог данных) и ежедневный бэкап `birzha-backup.timer`;
4. выкладывает код в `/opt/birzha/app` и запускает сервер (через `update.sh`);
5. настраивает nginx: проксирование WebSocket, gzip, заголовки безопасности,
   не больше 10 попыток входа в минуту с одного IP;
6. получает сертификат Let's Encrypt и включает редирект на HTTPS
   (продление — автоматически, таймером certbot);
7. включает брандмауэр: открыты только SSH, 80 и 443.

## Обновление

С Windows: `.\deploy\deploy.ps1 -Server game.example.ru`

Вручную: загрузите свежие `server/` и `deploy/` и выполните `sudo bash deploy/update.sh`.

`update.sh` ставит зависимости в отдельный каталог, подменяет им рабочий и перезапускает
службу. Если новая версия не ответила на `/healthz` за 20 секунд, возвращается прежняя
(неудачная остаётся в `/opt/birzha/app.failed` для разбора).

## Повседневные команды

| Задача | Команда |
|---|---|
| Состояние службы | `systemctl status birzha` |
| Журнал в реальном времени | `journalctl -u birzha -f` |
| Перезапуск (партии сохранятся) | `sudo systemctl restart birzha` |
| Проверка | `curl -fsS http://127.0.0.1:8792/healthz` |
| Бэкап вручную | `sudo -u birzha /usr/local/bin/birzha-backup` |
| Список бэкапов | `ls -lh /var/lib/birzha/backups` |
| Журнал nginx | `tail -f /var/log/nginx/birzha.error.log` |

### Восстановление из бэкапа

```bash
sudo systemctl stop birzha
sudo tar -xzf /var/lib/birzha/backups/birzha-YYYYMMDD-HHMMSS.tar.gz -C /var/lib/birzha
sudo chown -R birzha:birzha /var/lib/birzha
sudo systemctl start birzha
```

## Настройки (`/etc/birzha.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `HOST` | `127.0.0.1` | на каком адресе слушает Node.js (наружу — только через nginx) |
| `PORT` | `8792` | внутренний порт |
| `DATA_DIR` | `/var/lib/birzha` | аккаунты, сохранённые партии, бэкапы |
| `TRUST_PROXY` | `1` | доверять `X-Real-IP`/`X-Forwarded-*` от nginx: реальный IP игрока и флаг `Secure` у куки. Заголовки принимаются только с локальных и внутренних адресов (nginx на этой машине, Docker); без прокси переменную не задавайте |
| `ROOM_TTL_HOURS` | `12` | через сколько часов без игроков удалять заброшенную комнату |
| `TM_DEBUG` | — | `1` включает отладочную кнопку внеочередного события (не для продакшна) |

После правки: `sudo systemctl restart birzha`.

### Магазин и реклама (необязательно)

Пока переменные ниже не заданы, магазина и рекламы нет вовсе: игра работает как раньше,
к платёжным системам сервер не обращается. Пошаговая настройка для владельца —
`MONETIZATION.md` в корне проекта, устройство — `docs/MONETIZATION-SPEC.md`.
Флаги принимают `on`/`off` (а также `1`/`0`, `true`/`false`, `yes`/`no`). Неверное значение
выключает только соответствующего провайдера; причина пишется в журнал при старте вместе
со строкой «Магазин: ЮKassa — вкл/выкл, …» (`journalctl -u birzha -n 30`).
**Секрет** — значение нельзя показывать никому и класть в репозиторий.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `YOOKASSA_SHOP_ID` | — | shopId магазина ЮKassa (ЛК → Интеграция → Ключи API); для проверки — shopId тестового магазина |
| `YOOKASSA_SECRET_KEY` | — | **Секрет.** Секретный ключ ЮKassa |
| `YOOKASSA_RETURN_URL` | — | адрес сайта без пути, `https://game.example.ru`: туда ЮKassa возвращает игрока после оплаты |
| `YOOKASSA_RECEIPTS` | `off` | `on` — передавать чек 54-ФЗ (ИП/ООО с «Чеками от ЮKassa»; игрок укажет email). Самозанятым — `off` |
| `YOOKASSA_VAT_CODE` | `1` | ставка НДС позиции чека: 1 — без НДС, 4 — 20%, 7 — 5%, 8 — 7%, 11 — 22% |
| `YOOKASSA_TAX_SYSTEM` | — | система налогообложения в чеке (1–6), если у магазина их несколько |
| `YOOKASSA_PAYMENT_SUBJECT` | `service` | признак предмета расчёта: `service`, `intellectual_activity` или `another` (уточните у бухгалтера) |
| `YOOKASSA_IN_RUSTORE` | `off` | `on` — показывать оплату картой/СБП и в сборке для RuStore (сначала проверьте правила RuStore) |
| `YOOKASSA_WEBHOOK_IP_CHECK` | `on` при `TRUST_PROXY=1` | принимать уведомления только с адресов ЮKassa (выключенная проверка — предупреждение в журнале при старте; поток уведомлений с одного адреса ограничен в любом случае) |
| `YOOKASSA_ALLOW_TEST` | `off` | `on` — засчитывать платежи **тестового магазина** ЮKassa (`test:true`). Включайте только на время проверки с ключами тестового магазина и выключите, перейдя на боевые: иначе любой «оплатит» тестовой картой. Пока выключено, тестовый платёж не выдаётся, а в журнале — подсказка |
| `RUSTORE_KEY_ID` | — | keyId ключа API RuStore (Консоль → API RuStore) |
| `RUSTORE_PRIVATE_KEY` | — | **Секрет.** Приватный ключ API RuStore: base64 одной строкой, как выдала консоль |
| `RUSTORE_PRIVATE_KEY_FILE` | — | вместо предыдущей: путь к файлу с тем же base64 (например, `/etc/birzha/rustore.key`, права 640, `root:birzha`) |
| `RUSTORE_APP_ID` | — | id приложения в RuStore Консоли (число) |
| `RUSTORE_ALLOW_SANDBOX` | `off` | `on` — засчитывать тестовые платежи песочницы RuStore (только на время проверки!) |
| `GOOGLE_PLAY_PACKAGE` | — | имя пакета, `com.xstatem.trademonopoly` |
| `GOOGLE_PLAY_SERVICE_ACCOUNT` | — | **Секрет.** Путь к JSON-ключу сервисного аккаунта Google, например `/etc/birzha/google-play.json` (права 640, `root:birzha`) |
| `GOOGLE_PLAY_ALLOW_TEST` | `off` | `on` — засчитывать покупки лицензионных тестеров Google Play |
| `ADS_REWARD_POINTS` | `0` | очков за досмотренное видео; `0` — реклама выключена. Рекомендуется `10` |
| `ADS_DAILY_CAP` | `5` | видео в сутки на аккаунт (сутки по Москве); с Премиумом вдвое больше |
| `ADS_COOLDOWN_SEC` | `180` | пауза между засчитанными видео, секунд |
| `ADS_MIN_WATCH_SEC` | `10` | раньше этого билет на видео не гасится (Яндекс и AdMob без SSV) |
| `ADS_MIN_ACCOUNT_AGE_HOURS` | `0` | видео с наградой — только аккаунтам старше стольких часов (например, `24`): меньше смысла заводить аккаунты ради очков |
| `ADS_YANDEX` | `on`, а при `ADMOB_SSV=on` — `off` | видео Яндекса в сборках `direct` и `rustore`. **Без серверной проверки**: см. ниже |
| `ADMOB_SSV` | `off` | `on` — очки за AdMob только по подписанному колбэку Google |
| `ADMOB_AD_UNITS` | — | числовые id блоков AdMob через запятую (часть после «/»); колбэки других блоков отклоняются |
| `YANDEX_ADS_S2S_SECRET` | — | зарезервировано: у Яндекса пока нет серверного колбэка награды, сервер переменную не использует |
| `SHOP_SELLER` | — | продавец для подвала магазина: «ИП Иванов И. И., ИНН …, support@…» |
| `SHOP_OFFER_URL` | — | ссылка (https) на публичную оферту |
| `SHOP_PRIVACY_URL` | — | ссылка (https) на политику конфиденциальности (RuStore требует её для рекламы) |
| `PAYMENTS_MOCK` | — | `1` — тестовая оплата без денег, только для разработки и тестов; при `NODE_ENV=production` не включается |
| `PAYMENTS_MOCK_FORCE` | — | `1` — всё же включить тестовую оплату при `NODE_ENV=production`. **Только на отдельном проверочном сервере**: любой вошедший получает товары бесплатно |
| `YOOKASSA_API_URL` | `https://api.yookassa.ru/v3` | только для автотестов (поддельная ЮKassa); учитывается лишь вместе с `PAYMENTS_MOCK=1` |

**Видео Яндекса засчитываются «на честном слове».** У Яндекса нет серверного подтверждения
награды, а тип сборки (и с ним провайдера рекламы) называет само приложение. Скрипт может
получать билеты и гасить их без показа видео — с любого аккаунта, в том числе через сайт.
Накрутку ограничивают только `ADS_DAILY_CAP`, `ADS_COOLDOWN_SEC`, `ADS_MIN_WATCH_SEC` и
`ADS_MIN_ACCOUNT_AGE_HOURS`: на аккаунт — не больше `ADS_DAILY_CAP × ADS_REWARD_POINTS` очков
в сутки. Держите награду скромной. Проверенные награды — только AdMob с `ADMOB_SSV=on`. Включив
его, вы выключаете Яндекс по умолчанию (иначе SSV обходился бы через «сборку direct»). Если
Яндекс всё же нужен в RuStore-сборке, задайте `ADS_YANDEX=on` явно.

**Возвраты.** ЮKassa — по уведомлению `refund.succeeded`: полный возврат или несколько частичных
на всю сумму снимают покупку; деньги, вернувшиеся раньше выдачи, товар не выдают. Google Play — по
`voidedpurchases` раз в 6 часов. RuStore уведомлений не шлёт: сервер сам перепроверяет выданные
счета за последние 60 дней (каждый раз в сутки) и снимает покупку со статусом `REFUNDED`/`REVERSED`.
Если очки к возврату уже потрачены, на аккаунте остаётся долг: следующие очки (победы, покупки,
видео) сначала гасят его, а магазин показывает игроку сумму долга.

Ключи-файлы кладите в `/etc/birzha/` (служба читает `/etc`, а писать может только в `DATA_DIR`):

```bash
sudo install -d -m 750 -o root -g birzha /etc/birzha
sudo install -m 640 -o root -g birzha google-play.json /etc/birzha/google-play.json
```

Адреса для личных кабинетов провайдеров:

- уведомления ЮKassa (события `payment.succeeded`, `payment.canceled`, `refund.succeeded`):
  `https://game.example.ru/api/shop/yookassa/webhook` — нужен HTTPS на 443, его настраивает `install.sh`;
- серверный колбэк AdMob (SSV): `https://game.example.ru/api/ads/admob-ssv`.

nginx менять не нужно: `/api/` проксируется целиком, строка запроса не меняется (это важно для
подписи AdMob). Заказы хранятся в `DATA_DIR/orders.json` — это учёт оплат, он попадает в ежедневный
бэкап вместе с `users.json`; удалять его нельзя.

**Render (бесплатный план)**: диск там временный — `users.json` и `orders.json` пропадают при каждом
деплое. Платежи на нём не включайте: только свой сервер (этот каталог) или Render с постоянным диском.

## Мобильное приложение со своим сервером

Приложение (Capacitor, папка `mobile/`) ходит на адрес, зашитый при сборке.
Чтобы оно подключалось к вашему серверу:

- **GitHub Actions**: *Actions → Android APK → Run workflow*, в поле «Адрес онлайн-сервера»
  укажите `https://game.example.ru`. Чтобы это был адрес по умолчанию для всех сборок (и для
  push), задайте в **Settings → Secrets and variables → Actions → Variables** переменную
  `TM_SERVER_URL` = `https://game.example.ru` — править workflow не нужно. Сборки с этим адресом
  по-прежнему публикуются в Releases. Сборки для RuStore и Google Play делайте только с адресом
  своего сервера: на бесплатном Render магазина нет (сборка предупредит об этом в журнале).
- **Локальная сборка**: в `mobile/` выполните `TM_SERVER_URL=https://game.example.ru npm run sync`
  (или `npm run android:apk`), подробнее — `mobile/README.md`.
- Запасной адрес на случай сборки без переменной — `DEFAULT_SERVER` в `server/public/native.js`.

Адрес должен быть `https://` — Android запрещает незащищённые соединения.

## Docker вместо systemd

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

Данные — в томе `birzha-data`. Порт открыт только на `127.0.0.1:8792`: перед контейнером
поставьте nginx с конфигом `deploy/nginx-birzha.conf` (подставьте `__SERVER_NAME__` и `__PORT__`).
Если открываете порт контейнера наружу без nginx, уберите из `docker-compose.yml` строку
`TRUST_PROXY`: заголовки прокси тогда может подставить любой клиент.

## Переезд с Render и выбор адреса

- Игра должна жить в корне домена или поддомена (`https://game.example.ru/`), а не в подкаталоге:
  клиент, service worker и WebSocket используют абсолютные пути от корня.
- Выберите один адрес (с `www` или без) и используйте только его: вход в аккаунт и офлайн-сохранение
  хранятся в браузере отдельно для каждого адреса.
- На новом адресе браузерные игроки один раз войдут в аккаунт заново. Сами аккаунты переедут,
  только если перенести `users.json` со старого сервера (`-ImportData` / `--import-data`);
  у бесплатного Render диск временный, и там его может уже не быть.

## Если что-то пошло не так

- **Страница не открывается** — `systemctl status birzha nginx`, затем `journalctl -u birzha -n 50`.
- **Certbot не выдал сертификат** — проверьте A-запись (`dig +short game.example.ru` должен
  вернуть IP сервера) и что порт 80 открыт у хостинга; затем запустите `install.sh` ещё раз.
- **Онлайн-партия всё время «переподключается»** — WebSocket режет промежуточный прокси.
  Если перед сервером стоит Cloudflare, включите в нём WebSockets.
- **После обновления у игроков старый интерфейс** — service worker обновляется при
  следующем открытии страницы; обычная перезагрузка вкладки помогает сразу.
