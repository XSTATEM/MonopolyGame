# Симулятор баланса «Биржи» (tools/sim)

Прогоняет тысячи партий ботов на **настоящем** движке `server/public/engine.js` и
собирает статистику: кто и как выигрывает, когда банкротятся, сколько длится
партия, какие действия используются, как ведут себя рынок и денежная масса.
Обычный Node ≥ 18, без npm-зависимостей. Файл движка не меняется — симулятор
читает его как текст при каждом запуске, поэтому всегда работает с текущими
правилами.

```
node tools/sim/sim.js --games 2000 --players 4 --profiles engine,engine,greedy,saver --max-rounds 30 --seed 42 --out results.json
```

Справка по всем опциям — `node tools/sim/sim.js --help`.

## Быстрый старт

```bash
# эталон: 4 бота движка, партия на 30 раундов (прежнее умолчание новой комнаты)
node tools/sim/sim.js --games 1000

# сила стратегии: профиль против трёх ботов движка (места ротируются)
node tools/sim/sim.js --games 1200 --profiles engine,engine,engine,greedy

# подмена константы движка и настройки комнаты
node tools/sim/sim.js --games 2000 --override TURN_SALARY=600 --set startingCash=60000

# сравнить несколько значений одного параметра на одних и тех же партиях
node tools/sim/sim.js --games 400 --sweep "TURN_SALARY=0|450|1500"
node tools/sim/sim.js --games 400 --max-rounds 0 --sweep "tierForcedPaymentPct=[60,45,30]|[45,35,25]"

# кривая платы за отказ и цены выкупа (engine.js, FEE_CURVE_*): эффективная доля
# f(x) = x·(1 + K·x^P)·(4/min(N_MAX, активных))^N_EXP вместо доли держателей x;
# по умолчанию K = 1.5, P = 1, N_EXP = 3.5, N_MAX = 6.5 (BALANCE-REPORT.md, раздел 00),
# K = 0 и N_EXP = 0 — прежняя линейная плата байт в байт
node tools/sim/sim.js --games 400 --max-rounds 0 --hard-cap 1000 --sweep "FEE_CURVE_K=0|1|1.5"
node tools/sim/sim.js --games 300 --players 2 --max-rounds 0 --hard-cap 1000 --override FEE_CURVE_K=0 --override FEE_CURVE_N_EXP=0

# до/после правки правил: те же партии на копии старого движка и на текущем
node tools/sim/sim.js --games 1000 --profiles engine,engine,greedy,controller --seed 42 --engine old/engine.js --out before.json
node tools/sim/sim.js --games 1000 --profiles engine,engine,greedy,controller --seed 42 --out after.json

# партия до последнего выжившего (с предохранителем 300 событий)
node tools/sim/sim.js --games 300 --max-rounds 0

# фаззинг движка: случайные действия, ищем зависания и нарушения инвариантов
node tools/sim/sim.js --games 600 --profiles chaos,chaos,chaos,chaos --max-rounds 0 --hard-cap 150 --fail-on-anomaly

# сводка JSON — в файл или в stdout
node tools/sim/sim.js --games 500 --out sim.json --per-game
node tools/sim/sim.js --games 500 --json > summary.json
```

**PowerShell.** Значения с кавычками PowerShell 5.1 передаёт плохо — удобнее
JS-литералы без кавычек и `--set`: `--override TIER_VOL={A:1,B:1,C:1}`,
`--set tierForcedPaymentPct=[30,25,20]`, а `--settings` можно взять из файла:
`--settings @settings.json`.

Скорость: ~10–15 мс на партию в 30 раундов в одном потоке; 2000 партий на 16
ядрах — около 7 секунд. Партии без лимита раундов длятся в ~7 раз дольше.

## Профили стратегий

| профиль | что делает |
|---|---|
| `engine` | чистый `engine.botStep` — эталон, с которым сравниваются остальные |
| `passive` | ничего не покупает, всегда отказывается и платит, мер не применяет |
| `greedy` | покупает максимум доступного (до 25%) при каждом броске, любую недвижимость и улучшение |
| `saver` | держит резерв (50% старта или 30% капитала), покупает ≤5%; 1% — если это дешевле платы за отказ |
| `controller` | концентрируется на ≤3 компаниях до >50% (покупки + бартер), затем PR своих, негатив по чужим, сквиз-аут, инсайд, слияния, народное IPO; цену выкупа ставит у порога завышения |
| `realestate` | приоритет — города: покупает и улучшает, продавая ради этого акции |
| `leverage` | берёт кредит на весь лимит и покупает как `greedy`, гасит при запасе и берёт снова |
| `dodger` | проверка лазейки: при свободных акциях всегда покупает ровно 1% вместо платы за отказ |
| `chaos` | случайные действия из всего набора движка — фаззинг на зависания и ошибки, не для баланса |

`--profiles` задаёт профили по местам; список короче `--players` повторяется по
кругу. По умолчанию места **ротируются** (`--seat-mode rotate`): партия №i сдвигает
список на i, так что каждый профиль поровну сидит на каждом месте и выигрыш не
путается с преимуществом первого хода. `fixed` — как задано, `shuffle` — случайно.

Профиль переопределяет только те решения, которые ему важны. Всё остальное —
оплату назначенной цены выкупа, ренту за чужой город, ответы на сделки и т.п. —
решает сам движок, поэтому партия не встаёт на обязательствах.

В смешанном столе часть решений за ботов `engine` (купить ли по броску на чужую
компанию, сколько процентов, принять ли сделку от профиля) принимает драйвер, и он
повторяет логику **загруженного** движка: покупка — через `botBuyPct` (пакет А5: 5%
вместо платы за отказ, когда у компании есть другие держатели), порог сделки —
множитель из строки `const accept = canPay && got >= paid [* k];` в `botStep`
(после А5 `k = 1`). У движка без `botBuyPct` драйвер берёт `botChoosePct` и порог
`0.9` — как до пакета, поэтому прогон с `--engine` на старой копии совпадает с
прежними результатами байт в байт.

## Что в отчёте

- **Как заканчиваются партии** — лимит раундов / последний выживший / все банкроты /
  предохранитель / ЗАВИСАНИЕ / ОШИБКА; число раундов (биржевых событий), ходов и шагов движка.
- **Победы по профилям** — доля побед на одно место с 95% интервалом Уилсона
  (справедливая доля = 1/число игроков), средняя позиция, доля банкротств, доля
  ходов «без денег» (наличные < 5% стартового капитала), итоговый капитал p10/p50/p90;
  победы по местам (порядок хода).
- **Разрыв и неравенство** — отрыв победителя от второго, их отношение, коэффициент
  Джини итогового капитала (для 4 игроков максимум 0.75 — всё у одного).
- **Банкротства** — на партию, доля партий хотя бы с одним, номер события первого
  банкротства, причины: плата за отказ от покупки, назначенная цена выкупа, рента,
  налоговая проверка, взыскание кредита, аудит.
- **Лидерство** — смены лидера по капиталу (замер после каждого события) и «снежный
  ком»: как часто выигрывает лидер середины партии.
- **Действия** — среднее за партию по каждому типу (покупка, отказ с оплатой и без,
  рента, недвижимость, кредиты, каждая мера контроля, сделки принятые/отклонённые,
  шпионаж/дискредитация с успехом и провалом, слияния, шорты) и отклонённые движком попытки.
- **Пассивные события** — по ленте движка: принудительные продажи, просрочки и
  взыскания кредитов, шорты, конфискации, полные поглощения, пассивная рента,
  бонусы, налоги, типы карт новостей.
- **Рынок** — цена в конце партии относительно стартовой цены тира (по тирам и
  секторам), доля компаний у ценового пола, число компаний под контролем, слитых, купленных городов.
- **Денежная масса** — по номерам событий у активных игроков: наличные, акции,
  недвижимость, кредиты, итого (видно инфляцию или сжатие).
- **Потоки наличных** — сколько денег за партию приносит и забирает каждый тип
  действия (зарплата, покупки, биржевые события…), плюс долги банкротов, которые
  остались у получателей (деньги «из воздуха»).
- **Аномалии** — зависания, ошибки движка, нарушения инвариантов (нечисловые или
  отрицательные наличные у активного игрока, отрицательные доли, сумма долей >100%,
  плохие цены) с командой для повтора партии.

В JSON (`--out`) — то же самое полностью: `meta` (движок, его sha1, подмены, конфиг),
`summary` (все агрегаты, `moneyCurve` по событиям, `anomalies.hard` — дампы
состояния), с `--per-game` — ещё `games` (запись каждой партии). У `--sweep` —
`variants[]` со сводкой на каждое значение.

## Как это устроено

- **`engine-loader.js`** — исполняет `engine.js` в отдельном `vm`-контексте.
  `Math.random` там заменён генератором sfc32 с сидом `"<seed>#<номер партии>"`, поэтому
  результат не зависит от числа потоков, а любую партию можно повторить отдельно.
  `--override NAME=value` заменяет в исходнике `const NAME = <литерал>;` до исполнения;
  не нашли объявление — ошибка. Перед финальным `return` фабрики вставляется «крючок»,
  который отдаёт симулятору внутренние функции движка (стоимости мер, `botBuyPct`,
  `botChoosePct`, `getForcedPaymentPct` …) — профили считают ровно те же суммы, что и движок.
  Порог сделки ботов записан прямо в `botStep`, поэтому его множитель читается из
  исходника (`detectTradeAcceptMult`) и приходит в драйвер как `env.tradeAcceptMult`.
- **`runner.js`** — одна партия: комната создаётся как в офлайн-режиме
  (`freshRoom` → `updateRoomSettings` → `addPlayer` ботов → `maxRounds`; лимит берётся
  из `--max-rounds`, по умолчанию 30 — как у новой комнаты в движке), затем драйвер
  шаг за шагом выполняет по одному действию движка и собирает метрики. Если все игроки —
  `engine`, каждый шаг — просто `engine.botStep`.
- **`profiles.js`** — профили; **`helpers.js`** — контекст решений для них.
- **`stats.js`** — агрегация (средние, квантили, интервалы Уилсона, кривые).
- **`sim.js`** — CLI, пул `worker_threads` (по умолчанию до числа ядер), отчёт.
  Исходник движка (уже с подменами) готовится один раз в главном потоке — правка
  `engine.js` посреди прогона не даст потокам разные версии правил.
- **Проверка подмен.** Перед прогоном с `--override`/`--set` симулятор считает 16
  контрольных партий со всеми подменами и без каждой по очереди. Если итоги не
  изменились ни в одной — предупреждение: подмена в этой комбинации мёртвая (движок
  не читает константу, её перекрывает `room.settings`, или значение совпадает с текущим).
  Отключается `--no-probe`.
- **Зависания.** Партия считается зависшей, если `--stall-steps` шагов подряд состояние
  не меняется (ни записи в ленте, ни смены хода/броска/обязательств) или `--turn-stall`
  шагов не завершается ход. Такая партия (и упавшая с ошибкой) идёт в аномалии с дампом:
  состояние комнаты, последние действия драйвера, хвост ленты и команда повтора.

## Повтор партии

Каждый дамп аномалии содержит готовую команду, например:

```
node tools/sim/sim.js --profiles controller,chaos,engine --seed abc --games 1 --game-offset 37 --trace
```

`--game-offset N --games 1` считает ровно партию №N из большого прогона, `--trace`
печатает её ленту событий. Результат совпадает байт в байт с той же партией в пачке.

## Сравнение до/после (`--engine`)

Правку правил удобнее всего мерить на одних и тех же партиях: сохраните копию
`engine.js` до правки и прогоните оба файла с одинаковыми `--games`, `--profiles`
и `--seed` (пример — в «Быстром старте»). Партия №i в обоих прогонах начинается с
одного сида, так что разница в сводках — эффект правки, а не шум другой выборки.
Сводки отличаются байт в байт только `msPerGame` (время счёта); в `--out` ещё
`meta` (время создания, путь и sha1 движка).

Текущие умолчания движка, от которых отсчитываются такие сравнения: плата за отказ
от покупки `tierForcedPaymentPct = [60,45,30]` по кривой `FEE_CURVE_*` (K 1.5, N_EXP 3.5,
N_MAX 6.5). Длительность новой комнаты в игре — `settings.maxTurnsPerPlayer = 150`
(свои ходы у каждого, раунды считает `startGame`); симулятор её не применяет и играет
по `--max-rounds` (по умолчанию 30 раундов, `0` — до последнего выжившего).
Логику ботов `engine` в смешанном столе драйвер берёт из того же файла (см.
«Профили стратегий»), поэтому старая копия считается со старыми ботами, а новая —
с новыми.

## Свой профиль

Добавьте объект в `PROFILES` (`profiles.js`). Любой крючок можно не указывать —
тогда решает движок:

```js
cautious: {
  desc: "Покупает только голубые фишки (тир A), остальное — отказ.",
  stock(ctx, roll) {
    if (ctx.tier(roll.ticker) !== "A") return act("dividendFromRoll");
    const pct = ctx.affordablePct(roll.ticker, ctx.me.cash - 30000);
    return pct >= 1 ? act("buyFromRoll", pct) : act("dividendFromRoll");
  },
},
```

Крючки: `preRoll`, `stock`, `realEstate`, `postRoll`, `forcedPrice`, `respondTrade`,
`insider` (описание — в шапке `profiles.js`). Действие — `act("имяФункцииДвижка", ...аргументы
после room и playerId)`. Отклонённое движком действие драйвер больше не повторяет в той же
фазе хода, а после 8 действий за фазу ход принудительно идёт дальше.

## Ограничения

- Профили видят все чужие пакеты (в игре они скрыты до шпионажа; публична только
  суммарная доля компании «в руках игроков»).
- `--override` меняет только `const NAME = <литерал>;` верхнего уровня; литерал не должен
  содержать `;` внутри строк. Числа, «вшитые» в формулы (ставка кредита, ценовой импульс
  покупки и т.п.), так не подменить — для проверки такой идеи скопируйте движок во временную
  папку, поправьте и запустите с `--engine путь/к/копии.js`.
- Список констант-кандидатов — `--list-constants`. Не каждая из них что-то решает:
  например, `TIER_FORCED_PAYMENT_PCT` перекрыт настройкой комнаты
  `tierForcedPaymentPct` (по умолчанию `[60,45,30]`), поэтому плату за отказ меняйте
  через `--set tierForcedPaymentPct=[…]` — проверка подмен об этом предупредит.
- Счётчики пассивных событий опираются на теги и фрагменты текста записей ленты
  (`LOG_COUNTERS` в `runner.js`). Поменяется формулировка в движке — счётчик покажет 0,
  на ход партий это не влияет.
